# Тесты

Автотесты клиента `wb-mqtt-alice`. Написаны на стандартном `unittest`,
дополнительных пакетов для запуска не требуется.

## Запуск

Из корня репозитория:

```terminal
$ python3 -m unittest discover -s tests -t . -v
```

Отдельный файл:

```terminal
$ python3 -m unittest tests.test_relative_range -v
```

## Что покрыто

| Файл | Проверяет |
|------|-----------|
| `test_relative_range.py` | Относительные команды range («сделай теплее/холоднее»): прибавление к текущему значению, ограничение шкалой, а также что абсолютная установка не сломалась |

## Как устроены тесты

Тесты гоняют настоящий путь команды — от блока действия, каким его присылает
Яндекс, через `SioAliceHandlers` и `DeviceRegistry` до топика, в который клиент
публикует. Проверяется поведение целиком, а не отдельная функция-конвертер.

Заглушками закрыта только граница MQTT:

- **публикация** — вместо отправки в брокер запись в список `self.published`;
- **чтение текущего значения** — `read_retained_value` подменяется и возвращает
  заранее заданное значение.

Благодаря этому **брокер и сеть для запуска не нужны** — тесты идут и на
сборочной машине.

## Соглашения при добавлении новых тестов

- **Без сети и брокера.** Всё, что ходит наружу (MQTT, HTTP), заменяется
  заглушкой.
- **Самодостаточность.** Конфиги пишутся во временную директорию
  (`tempfile.TemporaryDirectory`), а не читаются из `configs/` по относительному
  пути — иначе тест ломается там, где этого каталога рядом нет.
- **Имя теста — это ожидаемое поведение**, например
  `test_warmer_does_not_go_above_the_maximum_of_the_scale`. По имени должно быть
  понятно, что проверяется, без чтения тела.
- **Структура given/when/then.** Для читаемости заводятся хелперы-намерения
  (`given_current_temperature`, `adjust_temperature`, `assert_temperature_set_to`),
  а не голые словари и ассерты в каждом тесте.
