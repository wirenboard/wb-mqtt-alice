# Тесты

Автотесты клиента `wb-mqtt-alice`. Написаны на `pytest` (с `pytest-asyncio`
для асинхронных тестов). Зависимости ставятся из `requirements-dev.txt`.

## Запуск

Из корня репозитория:

```terminal
$ pytest
```

Отдельный файл:

```terminal
$ pytest tests/test_relative_range.py
```

## Что покрыто

| Файл | Проверяет |
|------|-----------|
| `test_relative_range.py` | Команды range из Яндекса: относительные («сделай теплее»), абсолютные и отказы |

## Как устроены тесты

Тесты гоняют настоящий путь команды — от блока действия, каким его присылает
Яндекс, через `SioAliceHandlers` и `DeviceRegistry` до топика, в который клиент
публикует. Проверяется поведение целиком, а не отдельная функция-конвертер.

Заглушками закрыта только граница MQTT:

- **публикация** — вместо отправки в брокер запись в список `published`;
- **чтение текущего значения** — `read_retained_value` подменяется через
  `monkeypatch` и возвращает заранее заданное значение.

Обвязка собрана в фикстуре, которая даёт тестам структуру given/when/then.
Брокер и сеть для запуска не нужны — тесты идут и на сборочной машине.

## Соглашения при добавлении новых тестов

- **Без сети и брокера.** Всё, что ходит наружу (MQTT, HTTP), заменяется
  заглушкой.
- **Самодостаточность.** Конфиги пишутся во временную директорию (фикстура
  `tmp_path`), а не читаются из `configs/` по относительному пути — иначе тест
  ломается там, где этого каталога рядом нет.
- **Имя теста — это ожидаемое поведение**, например
  `test_relative_step_past_the_maximum_is_rejected`. По имени должно быть
  понятно, что проверяется, без чтения тела.
- **Структура given/when/then.** Для читаемости заводятся хелперы-намерения,
  а не голые словари и ассерты в каждом тесте.
